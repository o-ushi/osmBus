# 実装メモ（docs/spec_migration.md からの差分）

パッケージはすべて仕様の名前のまま現行安定版で解決できた（置き換えなし）。座標型に `latlong2`、HTTP に `http`、l10n に `flutter_localizations` / `intl` を追加している。

- §8.4 乗換 2 回: 文字どおり「B の降車停留所（＝目的地 550m 以内）から C へ乗り換える」と意味のない経路になるため、A→B の接続（B が目的地へ届かなくてよい）のうち徒歩が短い B を最大 5 本取り、B の U 以降の停留所から目的地へ届く C を 1 段探す形にした。比較回数 2000 の打ち切りは路線 A ごと。
- §8.3 / §8.4 乗換: 直通で目的地に着く路線 A からは乗換案を探さない。仕様では「同じ番号が直通にも乗換にも出ることがある」を許すが、並行して走る路線どうし（例: 35A→35B）の乗り継ぎが「1」「2+」列に並んで表が読みにくくなるため。届かない路線から直通路線への乗換は従来どおり出る。
- §4.2 停留所: Swift の `parseDetails` に合わせ、road-side（`stop` / `stop_entry_only` / `stop_exit_only` / `stop_entry` / `stop_exit`）を優先し、無いときだけ platform 系 role と role 空の `highway=bus_stop` 節を使う（和集合にすると同じ停留所が二重になるため）。
- §4.2 形状: Swift は way ごとに別セグメントだが、端点がつながる way は向きを揃えて 1 セグメントに連結し、途切れたら別セグメントにした（各 way の 400 点間引きは Swift と同じ）。
- §3.4 置き換え読み込み: `schemaVersion` が無いファイルは Swift 版の書き出しとみなして受け付ける。1 以外の値は拒否。
- §5.3 保存直後の同期: ダウンロード中は塊ごとに保存されるため、最後の保存から 2 秒後にまとめて `mergeAndPush` する。
- 同意: 設定のスイッチをオフにすると非表示のみ（ファイルは残す）。ファイル削除は別ボタン「同意を撤回してデータを削除」。
- 番号表の純粋ロジックは `lib/models/bus_matrix.dart`、テスト用の路線生成は `test/fixtures.dart` に置いた（仕様の配置表に無いファイル）。
- Dart のパッケージ名は小文字のみのため `osmbus`。Android の `namespace` も `com.osamushikubo.osmbus` のままで、`applicationId` と iOS の Bundle ID は `com.osamushikubo.osmBus`。
- `Runner.entitlements` には仕様の 2 キーに加え、iCloud Documents に必要な `com.apple.developer.ubiquity-container-identifiers` も入れた。
- §11 UI: 仕様は Material 3 だが、利用者の指示で Swift 版の見た目に合わせた（クリーム地の方眼、オレンジ枠のカード、青い番号バッジ、乗車中はオレンジ）。画面は Swift と同じく「マトリクス（番号表）」と「番号入力（判定＋テンキー）」の 2 つで、右上「…」メニューか左端からの右スワイプで切り替える。設定と目的地選びはシート。
- §11 判定の色: Swift と同じく「◯◯だったら乗ってください！」は黄、見送りは赤、乗車中は緑。概算到着の 1 行は仕様どおり残した。
- §11 同意: Swift 版（同じバンドル ID）が接頭辞なしの UserDefaults に書いた `privacy.thirdPartyConsent.version` を起動時に引き継ぎ、Flutter 側で変えたときも同じキーへ書き戻す。
- UI テスト用に `TripController.requestsLocationOnLaunch` と `debugSetOrigin` を足した（`integration_test/app_flow_test.dart`）。


- **路線の保管庫（仕様外の追加）**：正本とは別に `Documents/osmBus/bus-route-archive.json` を持つ。保存のたびに形状付きの路線をここへ足し、消すことはない（置き換え読み込み・同意撤回・OSM 版更新による形状の取り消しでも残る）。正本が壊れていたら `.corrupt-<日時>` として脇へ移し、保管庫から立て直す。再取得時は OSM の版が同じ路線の形状を保管庫から戻し、通信を省く。形式は正本と同じなので、そのままバックアップとして読み込める。`UIFileSharingEnabled` / `LSSupportsOpeningDocumentsInPlace` により「ファイル」アプリから見える。設定に件数・復元・書き出しを追加。アプリ削除では消えるため、外へ残すには書き出しを使う。
- §10 番号表の重複除去: 仕様のキーは「方位|列|番号」だが、同じ番号が乗換1と2+の両方に並ぶため「方位|番号」にした。乗換の少ない列を優先し、同じ列なら徒歩合計→乗車距離の小さい方を残す（フラット表示も同じ）。
- 地図タイルと地名検索の予備: 回線の DNS が `tile.openstreetmap.org` / `nominatim.openstreetmap.org` を引けない環境（ベトナムの VNPT 回線で確認）では地図が空白になるため、タイルは OSM France（`tile.openstreetmap.fr/osmfr`）を `fallbackUrl` に、検索は Photon（`photon.komoot.io`）を予備にした。CARTO はアプリからだと API キーを要求されるため使わない。
- 出発地の手動指定（Swift の manualOrigin と同じ）: 現在地の行の地図ボタン／行のタップで地図シートを出発地モードで開く。シート上部で出発地／目的地を切り替えられる。手動出発地は「出発地: 地名」と緑のピンで表示し、×で現在地に戻す。保存はしない。番号表・判定・ダウンロードは手動出発地を優先し、乗車中の「あと」は GPS で測る。

## Swift 版との差分の取り込み（仕様外の追加）

Swift 版にあって Flutter 版に無かった機能を移した。Google API（Routes / API キー・お試し枠・Google ルート図）は移行の制約どおり移していない。地図の背景だけは後から Google マップに対応した（下の「Google マップ」）。

- **Google マップ**（Swift の GMSServices）: 地図 3 画面（番号表のルート図・地図シート・路線図）は `ui/bus_map.dart` の `BusMap` で描き、キーがあって設定「Google マップを使う」がオンなら Google、それ以外は従来の OSM タイル。路線と停留所はどちらも端末内の OSM データで、Google 表示でも OSM の出典を出す。キーはネイティブ側が持つ（チャネル `osmbus/google_maps`）。iOS は設定画面で入れたキー（Swift 版と同じ Keychain 項目 `google.apiKey.userOverride` なので Swift 版のキーも使える）→ ビルド時のキー（`ios/Flutter/Secrets.xcconfig` の `GOOGLE_MAPS_API_KEY`、Git には載せない）の順。SDK は起動中にキーを差し替えられないため、変更は再起動で反映。Android の Maps SDK は manifest からしかキーを読まないので、`android/local.properties` の `MAPS_API_KEY` だけ（設定画面では変えられない）。

- **到着アラート**（`StopAlertSettings` / `RidingTracker` / `StopAlertPlayer`）: 降車停までの距離 3 段（既定 1000/400/100m）、内向きに越えたときだけ発火し、同時に越えたら一番近い 1 段だけ。アラームは遠い順に 1〜3 回。音は Swift と同じ 8 種で、iOS は同じ公開システムサウンドを鳴らし、無い環境（Android・シミュレータ）では似た合成音。音量はシステム音量に従う／スライダー。バイブは強さ 3 段。画面のアラートは前面ならダイアログを順番に、裏ならローカル通知（無音。音と振動はアプリが鳴らす）。乗車中はバックグラウンド測位（iOS は `UIBackgroundModes` location/audio、Android は常駐通知つきフォアグラウンドサービス）を続け、一番近い段に達したら裏での測位をやめる。
- **逆方向の警告**: 乗って 3 分以上、路線の 15% 未満、目的地から乗車時の 1.5 倍以上離れたら一度だけ警告。
- **キーパッド**: 結果表示後（⏎ のあと）の入力を「クリアして新規／継ぎ足し」から選べる。バイブ（強さ 3 段）とクリック音（音量）。
- **言語**: 端末に従う／English／日本語／Tiếng Việt を設定で選べる（Swift には「端末に従う」が無い）。
- **プラン管理と課金**: 買い切り `com.osamushikubo.osmBus.upgrade`（in_app_purchase）。購入・復元・デバッグビルドだけの切り替え。FREE は登録地・履歴とも 3 件、FREE に戻ると切り詰める。起動時に未完了の取引を受け取って反映する。Swift の `Transaction.currentEntitlements` に当たる静かな再確認は無いので、返金の取り消しは次の復元まで反映されない。
- **登録済みの場所・目的地の履歴**: 行き先シートの「履歴から探す」「登録地から探す」から。登録地は追加（自宅・会社・学校の候補つき）・編集・左スワイプで削除・今の目的地を長押しで登録。履歴は目的地を設定するたびに先頭へ（同じ地点は 1 件）。Swift の UserDefaults / Keychain の中身は引き継がない。
- **路線図**（メニュー）: Swift は Overpass に問い合わせるが、端末内の路線データから番号で探す（系統違いも拾い、近い順）。一覧から選ぶこともできる。番号バッジ長押しで乗車（降車は終点）。目的地なしで乗ったら「あと」は出さない。乗車中でもメニューの路線図は番号で探せる画面を開く。
- **距離バッジ**: 乗車中にタップでルート図、長押しでナビ中止（確認つき、目的地も消える）。
- **ヘルプ・プライバシーとデータ**: 内容はこの版の動き（Google を使わない、送信先は Overpass・OSM タイル・Nominatim/Photon・ストア）に合わせた。「すべてのデータを削除」は目的地・履歴・登録地・同意と路線データを消し、購入状態・一般設定・路線の保管庫は残す。
- **ディープリンク** `osmbus://destination?name=…&lat=…&lng=…&subtitle=…`（app_links）。
- Android は flutter_local_notifications のため core library desugaring を有効にした。
- **アイコン**: iOS のアプリアイコンは Swift の `AppIcon.appiconset/1024.png` から各サイズを作り、Android は Swift の `AppIcons/playstore.png` から各密度を作った。プラン管理とヘルプの見出しのアイコンは Swift の `ImageFree` / `ImagePremium`（`assets/images/plan_*.png`、1x/2x/3x）をプランに応じて出す。
- **開発者画面とログ（仕様外の追加、Swift にも無い）**: 設定の一番下のバージョン表示を 2 秒以内の間隔で 7 回押すと開く。端末・アプリの状態（位置は含めない）、ログの送信（共有シート：メール・ファイルなど。先頭に状態を付けた 1 つのテキストファイル）、コピー、消去、詳細ログ（位置の更新と降車停までの距離）、到着アラームと 5 秒後の通知の試験。ログは `Application Support/osmBus/logs/osmbus.log`（512KB で 1 世代ローテーション）に書き、位置は 0.001 度に丸める。捕まえていない例外（Flutter・プラットフォーム・Zone）、起動・前面/裏、位置の許可と追跡、乗車・アラーム発火・逆方向、通知、音の失敗、ダウンロード・Overpass の失敗、同期、購入、ディープリンクを記録する。
- **旅程の質の修正（§8 からの変更）**: 実データ（ハノイ 421 路線）で、寄り道の大きい乗換案や、路線図が街を横切る直線になる案が出ていたため直した。
  - 乗車距離と道のりは停留所の区間ごとに求める。両端の停留所が線から 120m 以内で、線の順番が合い、線に沿った長さが直線の 3 倍 + 300m 以下ならその区間は線をたどり、そうでなければ停留所どうしを直接結ぶ（way の順番・向きが崩れた路線で、乗車区間全体が 1 本の直線になり乗車距離が短く見えていた）。
  - 乗換案は徒歩最小ではなく、概算時間（徒歩 1.25m/s・バス 5.56m/s・乗換 1 回 300 秒）が最小のものを選ぶ。
  - 徒歩と乗車の合計が「出発地〜目的地の直線距離 × 2 + 2km」を超える案は出さない。
  - 「A に乗って B に乗り換え…」で、B 以降に出発地からそのまま乗れて時間が同じか短い案があれば、A を足した案は出さない。
- 番号表の距離順（フラット表示）: 徒歩（または合計）を 100m 単位で比べ、同じなら乗換の少ない順、次に乗車距離の短い順にした（数十 m の差で乗換 2 回の案が直通より上に並んでいたため）。
  - 乗換 2 回以上の案は、乗換 1 回以下の一番速い案より 5 分以上速いときだけ出す（端末内の計算では 3 本乗り継ぎの組み合わせが大量に出て、表が埋まっていたため）。
