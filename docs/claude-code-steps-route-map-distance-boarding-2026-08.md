背景（実装前に読む）

目的地未設定のまま OSM 路線図で乗車すると、「あと ○○km」が出る。

| 箇所 | 現状の距離の意味 |
|---|---|
| `MainViewModel.topScreenDistanceMeters` | 乗車中は `ridingAlightCoordinate` まで |
| `RidingTracker.resolveOSMAlightCoordinate` | 目的地が無くても **OSM 路線の最終停留所（終点）** を降車座標にする |
| `BusRouteMapView.distanceToAlightingStop` | 同じく最終停留所（なければ目的地）まで |

つまり目的地が無いときの「あと ○○km」は **ユーザーの行き先ではなく、そのバス路線の終点までの直線距離**。ナビとしての意味が薄いので、目的地未設定時は数値を出さず **「ー」** にする。

トップ表の乗降は既に「長押しで乗車／降車トグル」。路線図の緑 `bus.fill`（乗車開始）だけがタップ開始になっていて操作感が違う。

## Step 1 — 目的地未設定の「あと ○○km」を「ー」にする

### やってよい範囲

- `MainViewModel.topScreenDistanceMeters`（または距離を決める薄いヘルパー）
- `TopDistanceBadge` の表示（optional メートル対応が必要なら）
- `MainView` のツールバーでバッジを出す条件
- `BusRouteMapView` の `ridingSummaryBar` / `distanceToAlightingStop`（路線図内の距離表示がある場合）
- 必要なら `help_距離_body` など距離説明の 1 行追記（`ja`/`en`/`vi`）

### やること

1. **意味の整理（コードコメントで残す）**
   - 目的地あり・未乗車: 現在地 → 目的地
   - 目的地あり・乗車中: 現在地 → 今の降車停（Google レグ or OSM 側の解決結果）
   - **目的地なし**: 距離数値は出さない（OSM 終点までの距離を「あと」に使わない）

2. **表示**
   - 乗車中かつ目的地未設定のとき、距離バッジは消さず残してよい。値は **`ー`**（既存の `—` / `"—"` 表記に合わせる。`BusKeypadView` や表の空セルと同じ）。
   - 「あと」ラベルは残して値だけ `ー`、でも全体が分かりづらいなら「あと」＋`ー` のまま（現行 `TopDistanceBadge` レイアウト維持を優先）。
   - 色バンド: 数値が無いときは中立（secondary / グレー系）。赤や橙で煽らない。

3. **路線図内**
   - `BusRouteMapView` のサマリー距離も同じルール（目的地無しなら `ー` または距離非表示。サマリーが距離必須なら `ー`）。

4. **降車座標そのもの**
   - このステップで `resolveOSMAlightCoordinate` の終点フォールバックを消す必要はない（距離アラート等の別問題）。**表示だけ**「あと」に載せない。
   - ただし目的地無しで終点までの距離アラートが鳴るなら、アラート側も抑制してよい（ユーザーが「意味がない」と言っているのと同じ根拠）。抑制するなら報告に書く。

### やってはいけないこと

- 目的地があるときの距離定義を変えること。
- `TopDistanceBadge` の font / padding 定数を変えること。
- Step 2 のツールバー乗降 UI に手を出すこと。

### 完了条件

- 目的地なしで OSM 路線図から乗車 → トップ（またはメイン）の距離が **「あと / ー」** 相当。終点までの km が出ない。
- 目的地ありで乗車 → 従来どおり降車停までの km。
- 目的地あり・未乗車 → 従来どおり目的地までの km。
- ビルドが通る。

## Step 2 — 路線図の乗車マークをバス番号にし、長押しで乗降

### やってよい範囲

- `BusRouteMapView.toolbarContent`（緑 `bus.fill` の置き換え）
- 乗車開始コールバック（`onStartRiding` / `beginRidingTransition`）と、降車（`endRiding` 相当）を路線図から呼ぶ接続
- `TransitBusLineBadgeLabel` の再利用（見た目は既存の青／橙）
- 長押しジェスチャ（トップ表と同趣旨。必要なら短い haptic）
- `ja`/`en`/`vi` の accessibility / 短いヒント文言
- 関連ヘルプ 1〜2 キーの追記があれば最小限で

### 現状

未乗車・路線ロード済みの trailing:

1. 緑 `bus.fill` → タップで `beginRidingTransition`（乗車開始）
2. `trash`（クリア）
3. 履歴・キーボード など

乗車中は leading に `TransitBusLineBadgeLabel(..., isRidingBus: true)`（ヒット不可）。

### やること

1. **緑の `bus.fill`（乗車開始ボタン）をやめる。**
2. その代わり、ロード中の路線の **バス番号バッジ**（`TransitBusLineBadgeLabel`、`ref`）を置く。
   - 未乗車: `isRidingBus: false`（ブランド青）
   - 乗車中（この路線で乗っているとき）: `isRidingBus: true`（橙）。leading 固定表示と二重なら、trailing の操作用に一本化してもよい（どちらに置くかは一貫していれば可。おすすめは **操作可能なバッジを trailing 側に残し、leading の静的バッジと役割が被るなら静的側を整理**）。
3. **長押し**で乗降を切り替える（トップの `BusNumberTableView` と同じ思想）。
   - 未乗車 → 乗車開始（既存 `beginRidingTransition` / `onStartRiding`）
   - すでにこの番号で乗車中 → 降車（`endRiding` / 乗換用の降車。メイン・トップ長押しと同じ経路を再利用）
   - 別番号に乗車中なら、既存の「長押しで乗り換える」挙動に合わせる（`handleRidingBusLongPress` 系があればそれを経由）。
4. **タップ**では乗車開始しない（誤発火防止。トップ表と同様、乗降は長押し専任）。
5. VoiceOver: 「長押しで乗車または降車」が分かるラベル／ヒント（既存キー `バス番号表_操作ヒント` の再利用可なら使う）。
6. `trash`・履歴・キーボードの位置関係は崩さない（バッジが `bus.fill` だったスロットを占める）。

### やってはいけないこと

- トップ表や Google `TransitRouteMapView` の乗降ジェスチャ仕様をこのステップで変えること（揃えるのは OSM `BusRouteMapView` 側）。
- 新しい乗降状態マシンを別実装すること。`MainViewModel` / `RidingTracker` の既存 API を呼ぶ。
- Step 1 の「目的地なしは ー」を巻き戻すこと。

### 完了条件

- 路線図に緑バスアイコンが無い。バス番号バッジがある。
- 長押しで乗車できる。もう一度長押し（または乗車中バッジの長押し）で降車できる。
- 短いタップだけでは乗車しない。
- 目的地なしで乗車しても Step 1 の距離表示が `ー` のまま。
- ビルドが通る。
