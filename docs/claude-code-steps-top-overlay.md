## 実装方針（レビュー結論・全ステップで守る）

ユーザー意図は「今のメイン画面（キーパッド判定）は残しつつ、日常の乗り換え操作は地図いらずのトップ画面でやる」こと。機能を二重実装しない。

### 1. ユーザー意図に反する重複（こう扱う）

| 既存 | トップ画面 | 方針 |
|---|---|---|
| `DestinationBarView` / `CurrentLocationBarView` | 行き先・現在地 | **同じ View を再利用**。入力シート・地図ピッカーも `MainView` の既存 state を共有。 |
| `TransitRoutesSheetView` のバス番号長押し / `handleRidingBusLongPress` | 長押しで乗車・降車 | **同じトグル関数を呼ぶ**。トップ専用の乗車状態を作らない。 |
| 経路一覧タップ / `TransitRouteMapView` / ツールバー地図 | バス番号タップでルート図 | **既存のルート図表示経路を呼ぶ**（どのルートにそのバスが載っているかを渡す）。地図エンジンを新しく作らない。 |
| `ResultBannerView` の「乗車開始」「降車」 | 長押しトグル | トップ画面では長押しが主操作。メイン画面のボタンは残す（キーパッド派の動線）。トップ側に同じボタンを増やさない。 |
| 「経路を見る」シート | 方向×乗換の表 | トップが候補の一覧になる。シートはメイン画面側の詳細用として残す。トップに「経路を見る」ボタンを置かない。 |
| 乗車中の距離（現状は **今乗っているバスの降車停** までの直線距離） | `[距離]` | **同じ定義を使う**（ゴール地点そのものではない）。色分けもこの距離。定義を勝手に「最終目的地までの距離」に変えない。バグ修正で「次の降車停」に正しく切り替える。 |

### 2. ゾンビ化しやすいもの（削除はユーザー確認なしでしない）

- メイン画面全体（キーパッド・判定バナー・経路ボタン）→ メニュー「メイン画面」で残す。
- シェイクで地図、ツールバーの地図、左上「乗車中」→ トップ実装後も動くこと。このファイルの後半ステップでも勝手に消さない。
- OSM 乗車 (`BusRouteMapView` / `startRidingFromOSMMap`) → トップ表は Google Routes の蓄積経路が主。OSM 経路はトップ表に無理に混ぜない。

### 3. 冗長な動線（トップ完成後の主従）

- **主**: トップ表のバス番号（タップ＝図、長押し＝乗降）。
- **従**: メイン画面キーパッドで「このバスに乗ってよいか」判定。
- 乗り換えは「降車ボタン → メインに戻る → 番号入力 → 乗車開始」を必須にしない。長押しトグルで完結させる（Step 1 のバグ修正がその前提）。

### 4. ヘルプ整合（Step 6 で直す。それまでは文面変更しない）

現状ヘルプはトップ画面を知らない。

- `help_経路_body`: 「メイン画面の経路ボタン（または振る）」が主、と書いてある。
- `help_乗車中_body`: 乗車開始ボタン / 経路候補の長押し / カードの降車ボタンが主。トップのタップ・長押し・距離色がない。
- `help_目的地_body` / `help_現在地_body`: 「画面上部」はトップでも同じだが、トップが既定画面になるなら一言必要。

### 5. その他

- 乗車中は `MainView` が `refreshTransitRoutes` を止めている。乗り換え後も **蓄積済み** `accumulatedTransitRoutes` から次レグを取る。乗り換えのたびに API を叩き直さない。
- `clearBusNumber()` は入力・判定・`boardingRoute`・乗車状態を全部消す。降車トグルでこれを使うと次の乗車が組みづらい。Step 1 で「降車だけ」と「番号クリア」を分ける。
- 方向は既存 `GoogleRoutesAPIService` の方位（北西・南東・南など）を使う。ユーザー表の「北西 / 南東 / 南」はハノイ例。実データに出た方位だけ行を出す。空行を埋めない。
- 乗換回数は **バスレグ数 − 1**（バス1本＝直通、2本＝乗換え=1、3本以上＝乗換え≧2）。徒歩・地下鉄レグはバス乗換カウントに入れない（他交通は既存 `transitOtherTransitLineLabels` と同様、表セルには出さない）。

## Step 1 — 乗り換え後に距離が更新されない不具合

### やってよい範囲

距離・乗車状態のロジックのみ。トップ画面 UI は作らない。

### 不具合

経路一覧でバス番号を長押しして降車（同一番号なら `handleRidingBusLongPress` → `clearBusNumber()`）し、続けて次のバスを長押しして乗車中にしても、距離（今のレグの降車停までの直線距離）が次レグに切り替わらない。

### 原因の当たり（実装前にコードで確認し、違ったら正しい原因を直す）

1. `MainView.handleRidingBusLongPress` が同一番号なら `viewModel.clearBusNumber()` しており、`boardingRoute` まで消える。
2. 次バスの `startRidingForBusSelection` が `accumulatedTransitRoutes[routeIndex]` の **最初に一致するバスレグ** を使うため、既に降りたレグの降車停のままになる。
3. 乗車中は位置更新で `refreshTransitRoutes` しないため、古いルートのまま最初のレグにマッチし続ける。
4. `RidingTracker.buildRidingState` の降車座標が次レグの `arrivalStopLocation` に差し替わらない。

### 直すこと

- **降車**は乗車状態だけ終了する。バス番号入力欄や経路データベース、目的地は消さない。`clearBusNumber()` を降車トグルに使わない。
- **次バスへ乗車**するときは、指定ルート（なければ蓄積ルート群）の中から、その番号の **まだ乗っていない／現在地以降のバスレグ** を選ぶ。既に通過した最初のレグに再マッチしない。
- `RidingTracker` の `alightCoordinate`・ポリライン・`boardingStopDistanceToDestination`・距離アラート閾値を、そのレグで作り直す。既存の `boardingLocationOverride`（乗り換え時は現在地を乗車点にする）は維持する。
- 経路一覧・経路地図の長押しは、この新しいトグル／レグ選択を通す。UI 文言は最小限（必要なら「降車しました」程度）。
- `TransitRouteMapView` の距離表示（`currentLegAlightingCoordinate`）も、乗車中バスが変わったら次レグの降車座標を使うことを確認する。

### やってはいけないこと

- トップ画面、距離の色、メニュー項目。
- ヘルプ全文の書き換え（このバグに直結する1文以外）。
- 距離の定義を「最終目的地までの直線」に変更すること。

### 完了条件

- ルート例: バスA → 乗換 → バスB。A 長押しで乗車、A 長押しで降車、B 長押しで乗車、とすると距離の基準が B の降車停（または目的地方面の到着点）になる。
- 降車しても目的地・蓄積経路・現在地は残る。
- 既存のメイン画面「降車」ボタンも、乗車終了として同じ安全なクリアを使う（番号クリアと混同しない）。キーパッドのクリアボタンの意味は変えない。

## Step 2 — トップ画面シェルと「メイン画面」切り替え

### やってよい範囲

画面の被せ方とメニュー。表・距離色・乗降ジェスチャはプレースホルダでよい。

### やること

- 既定表示を **トップ画面** にする。既存 `MainView` の中身（キーパッド判定 UI）は残し、トップの下（または切替先）に置く。
- トップはメインの上に被せる（フルスクリーン）。ツールバー右の `...`（`MoreActionsMenuView`）はトップからも使える。
- メニュー先頭付近に「メイン画面」を追加。タップでトップを外し、今のメイン画面を出す。
- メイン画面からも `...` でトップに戻れるようにする（項目名は「トップ画面」または同等。ja/en/vi）。
- 行き先・現在地・距離・表の枠だけ置く。中身は「未接続」でよい。既存の sheet（目的地、履歴、設定、ヘルプ、経路一覧、地図）の presenter は `MainView` に残し、トップから後で呼べるように state を共有する。

### やってはいけないこと

- Step 1 の乗車ロジックを巻き戻す。
- メイン画面の削除、キーパッド削除。
- バス表の本実装、距離の色。

### 完了条件

- 起動するとトップ（枠だけ）が見える。
- `...` → メイン画面 → キーパッド付きの従来 UI。
- `...` → トップ画面（または同等）で戻れる。
- 設定・ヘルプなど既存メニューは両方から開く。

## Step 3 — 行き先・現在地・距離（色付き）

### やってよい範囲

トップヘッダー3行。表はまだ枠のままでよい。

### やること

レイアウト（ユーザー指定）:

```
                    [...]  ← 既存メニュー
[行き先]  OOOOOOO   ← メインと同じ入力
[現在地]  XXXXXXXX  ← メインと同じ入力
[距離]    OOkm      ← 残り距離で背景色
```

- `DestinationBarView` / `CurrentLocationBarView` を再利用。タップで既存シート、地図ボタンで既存 `MapLocationPickerView`。乗車中にメインが入力を disable しているならトップも同じ。
- 距離は Step 1 後の定義: 乗車中なら **現在レグの降車停** までの直線距離。未乗車なら目的地までの直線距離（現在地が取れるとき）。単位は 1km 以上 `X.X km`、未満は `XXX m` など既存アプリの距離表示に合わせる。
- 背景色（距離欄のみ）:

  - ≧ 3km … 青
  - ≧ 1km … 緑
  - ≧ 500m … 黄
  - ≧ 200m … 橙
  - < 200m … 赤

- 位置が無い・目的地が無いときは色を塗らずプレースホルダ。
- 色は Color+Contrast / ダークモードで文字が読めること。

### やってはいけないこと

- バス表の本実装。
- 距離アラート閾値設定（`StopAlertSettings`）の数値をこの色バンドに合わせて変えること。アラート設定と色バンドは別。

### 完了条件

- トップから行き先・現在地をメインと同じ手順で変えられる。
- 乗車／乗り換え後、距離の数字が Step 1 の基準点に追従する。
- 色が指定の閾値で変わる。

## Step 4 — バス番号表（方向 × 乗換）

### やってよい範囲

表のデータと表示。タップ・長押しの本接続は Step 5（このステップでは表示とアクセシビリティまで）。

### やること

`viewModel.accumulatedTransitRoutes` から表を組む。

列:

- 方向
- 直通（バスレグ 1）
- 乗換え=1（バスレグ 2）
- 乗換え≧2（バスレグ 3+）

行: そのルート群に実際にある方位。方位の求め方は既存のルート方向バッジ／ポリライン方位と揃える。

セル: その（方向, 乗換カテゴリ）に属するルートの **乗車すべきバス番号**（そのルートの最初のバスレグの番号）。同じ番号が複数ルートにあれば1回だけ出す。1セルに複数番号は縦に積む（ユーザー表の 60B / 74 のように）。

経路が空・読込中・失敗のときは既存の経路状態（`transitRoutesLoadState`）に合わせた表示。トップに「経路を見る」ボタンは置かない。必要なら小さな再読み込みだけ。

### やってはいけないこと

- ジェスチャで乗車・地図を本接続（見た目のボタン化は可、挙動は Step 5）。
- ルート API の呼び出し方を変える。既存 `refreshTransitRoutes` を使う。

### 完了条件

- 実データで、直通と乗換が列に分かれ、方向行に分かれて番号が見える。
- メイン画面の経路一覧に出るバスと矛盾しない（同じ蓄積データ）。

## Step 5 — バス番号のタップ／長押し

### やること

- **タップ**: そのバス番号が載っている経路のルート図を出す。既存 `TransitRouteMapView` / `BoardingRouteMapCover` / `openRouteMap` 相当。複数ルートがある番号は、その番号を含む代表ルート（直通優先、だめなら所要時間最短など、既存の matching に近いもの）。
- **長押し**: 乗車中でその番号なら降車、それ以外ならその番号で乗車。**Step 1 のトグルとレグ選択を必ず使う。** 経路一覧の長押しと同じ関数。
- 乗車中の番号は既存バッジ（`TransitBusLineBadgeLabel` の riding スタイル）でハイライト。
- ハプティクスは経路一覧長押しに合わせる。

### やってはいけないこと

- 新しい RidingTracker。
- トップに「乗車開始」「降車」ボタンを追加すること。

### 完了条件

- トップだけで、図を見る → 乗る → 降りる → 次のバスに乗る、が完結する。
- 乗り換え後に距離（Step 3）が次レグに更新される（Step 1 の回帰）。
- メインの経路一覧長押しでも同じ。
