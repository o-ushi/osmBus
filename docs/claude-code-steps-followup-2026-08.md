## Step 1 — バス番号表ヘッダのアイコン化

### やってよい範囲

`BusNumberTableView` の列ヘッダ見た目と、それに必要なアクセシビリティ文字列。ソート・ジェスチャ・経路ロジックは触らない。

### やること

列ヘッダをテキストから **SF Symbol + 短い数字** にする。英語でも文字縮小が起きないこと。

| 列 | 表示 | 推奨 SF Symbol（なければ近いもの。新規アセット禁止） |
|---|---|---|
| 方向 | アイコンのみ | `location.north.line` または `safari`（方位が伝わるもの） |
| 直通 | アイコン + `0` | `bus.fill` |
| 乗換え1回 | アイコン + `1` | `arrow.triangle.swap` または `arrow.left.arrow.right`（乗換が伝わるもの。同じアイコンを1と2+で共用） |
| 乗換え2回以上 | 同じ乗換アイコン + `2+` | 上と同じ |

- `minimumScaleFactor` で英語ラベルを潰す現状はやめる。数字は縮小しない。
- VoiceOver は今と同じ意味を残す（`方向` / `直通` / `乗換1` / `乗換2+` の既存キーで `accessibilityLabel`）。見た目の `0` `1` `2+` だけにしない。
- アイコンは secondary、数字は semibold。列幅は番号セルが主で、ヘッダが番号を圧迫しない。

### やってはいけないこと

- セル内のバス番号バッジ、タップ／長押し。
- 表データの組み立て・ソート変更（Step 4）。
- ヘルプ全文（アイコン化した旨は Step 2 か最後でよい。このステップでは触らなくてよい）。

### 完了条件

- 言語を英語にしてもヘッダが1行・読めるサイズのまま。
- VoiceOver で「直通」「1 transfer」相当が分かる。
- 表の番号・乗降は Step 前と同じ。

## Step 3 — 路線図の下端バーをやめ、左上に距離ボタン

### やってよい範囲

`TransitRouteMapView`（と下端の `RouteMapSummaryBar` の利用箇所）。`TopDistanceBadge` の縦横比・フォント・padding は **変更禁止**。

### やること

1. 路線図下端の所要時間 + 直線距離（`routeSummaryBar` / `RouteMapSummaryBar`）を **出さない**。
2. その代わり、地図領域の **左上** に既存 `TopDistanceBadge` を置く。
   - 距離の定義は既存と同じ（乗車中かつこのルートに今のバスがあるとき：現在レグの降車停まで。`distanceToDestination` / `currentLegAlightingCoordinate`）。
   - 未乗車で路線図を開いているときも、既存 `viewModel.topScreenDistanceMeters` と同じ定義で出せるなら出す。出せないときはバッジを出さない（仮の 0m で赤くしない）。
3. **サイズ**: `TopDistanceBadge` 内部の `labelFontSize` / `valueFontSize` / padding を路線図用に変えない。ラッパーで scale しない。
4. **タップ**: 路線図を閉じて直前の画面に戻る（`dismiss()`）。ナビバーの閉じるボタンと同等。トップ／メインの距離バッジ（タップで路線図を開く）の挙動は変えない。
5. 右下の現在地ボタン（`MapLocationButton`）は残す。下端バーが消えたあと地図を食わない位置にする。
6. このステップで `RouteMapSummaryBar` の参照がゼロになったら、その型を削除してよい（所要時間表示の復活はしない）。文字列キー `直線距離` が他で未使用なら Step 11 まで残してよい。

### やってはいけないこと

- `TopDistanceBadge` の見た目定数変更。
- OSM の `BusRouteMapView` をこのステップで大きく作り直すこと（Google 路線図が対象）。OSM 側に同じ下端バーがあるなら、同じ方針で消して距離バッジに寄せてよいが、なければ触らない。

### 完了条件

- 路線図下に時間・直線距離バーがない。
- 左上の距離ボタンがトップ／メインのバッジと同じ大きさ。
- そのボタンをタップすると路線図が閉じ、トップ（または開く直前の画面）に戻る。

## Step 4 — バス番号表の並びを「徒歩合計」順にする

### やってよい範囲

`BusNumberTableView` の距離計算と `sortedEntries` / `appendNearest`。API は触らない。

### 現状

セル内は `origin → 最初のバスレグの乗車バス停` が短い順。降車後の徒歩が入らない。

### やること

各ルートについて:

- **乗車徒歩** = 出発地（渡されている `originLatitude` / `originLongitude`）→ そのルートの **最初のバスレグ** の乗車バス停
- **降車徒歩** = そのルートの **最後のバスレグ** の降車バス停 → 目的地

合計が小さい順にセル内を並べる。同じ番号が複数ルートにあるときは、合計が小さいルートを残す（今の `appendNearest` と同じ「1番号1つ」）。

目的地座標が表にまだ無い。`TopScreenView` / `MainView` から destination lat/lng を渡す。目的地や停留所座標が欠けたら、欠けた側は 0 とせず、今と同様 `nil` → そのエントリは後ろへ。

徒歩は既存 `GoogleRoutesAPIService.distanceMeters`（直線）。ルートに沿った徒歩距離 API は呼ばない。

### やってはいけないこと

- 方向行の順序を勝手に変える（方位の出現順は維持）。
- 乗換回数の列定義を変える。

### 完了条件

- 乗車停は近くても降車後が遠いルートより、合計徒歩が短いルートの番号が上（または同一番号ならそちらが採用される）。
- 座標が無いときはクラッシュせず、従来どおり表は出る。

## Step 6 — 乗車中でも出発地を現在地に更新できる

### やってよい範囲

現在地バーの enable 条件と、更新時に乗車状態を消さないこと。目的地バーの乗車中 disable は維持。

### 現状

トップ／メインとも `isInputDisabled: viewModel.ridingState != nil` で現在地バーもロック。↻ は蓄積経路があるとリセット確認。

### やること

- 乗車中でも現在地バーを操作できる（↻・必要なら地図指定も可）。
- ↻ は GPS を取り直し、手動出発地があれば外して **現在地を出発地にする**。
- **乗車中**は経路データベース・乗車状態・目的地を消さない。確認ダイアログでルート全消ししない。
- **未乗車**の ↻ は、蓄積経路があるときの既存リセット確認を維持してよい。
- 距離バッジは GPS 更新に追従（降車停までの直線は今の定義のまま）。

### やってはいけないこと

- 乗車中に目的地バーを編集可能にすること（Step 9 のスワイプ中止は別）。
- 乗車中の自動 `refreshTransitRoutes` を毎秒レベルで復活させること（位置ストリームの既存抑制は維持。ユーザー操作の更新だけ許可）。

### 完了条件

- 乗車中に ↻ でき、現在地ラベル／距離が新しい位置になる。
- 乗っているバス番号・降車停基準は維持（ルート全消ししない）。
- 未乗車の経路リセット確認は残る。

## Step 7 — バス番号表のスクロール

### やってよい範囲

`BusNumberTableView` / `TopScreenView` のレイアウト。ヘッダアイコン（Step 1）とソート（Step 4）は維持。

### やること

候補が多く表が画面下に切れるとき、**表の中身をスクロール**して隠れた番号を見られるようにする。

- 行き先・現在地カードは固定（一緒に流さないのが望ましい）。
- 表タイトル＋再読み込みは、可能なら固定、難しければ表と一緒でよい。
- お試し残り回数は表の外に出したまま、可能なら画面下に残す。
- 番号のタップ／長押しがスクロールと喧嘩しすぎない（短いドラッグはスクロール、長押しは乗降）。

### やってはいけないこと

- グリッド構造（方向 × 乗換）の廃止。
- 画面全体を無差別 `ScrollView` にして距離バッジやツールバーまで流すこと。

### 完了条件

- 方位・番号が多いデータで、下の番号までスクロールして長押しできる。
- 行き先バーは通常画面サイズでは見えたまま。

## Step 8 — 乗換降車時に出発地を更新して経路を取り直す

### やってよい範囲

長押し降車（同一バス番号で `endRiding`）の直後処理。乗車開始ロジックは壊さない。

### やること

乗り換えのために **今乗っているバスを長押しして降車した** とき:

1. 既存どおり `endRiding()`（番号欄・蓄積経路・目的地は消さない。`clearBusNumber()` は使わない）。
2. 現在地を取り直す（GPS。手動出発地はクリアして現在地を出発地にする）。
3. `refreshTransitRoutes(userInitiated: true)` で **新しい出発地から経路を取り直す**。
4. トップのバス番号表を新しい候補で出す。経路一覧シートは自動で開かない。

メイン画面の「降車」ボタンも同じ（乗換の入口がボタンでも揃える）。

次のバスへの長押し乗車は、取り直した蓄積ルートに対する既存 `startRidingForBusSelection` を使う。

### やってはいけないこと

- 最終降車（ナビ終了）まで毎回 API を撃つこと。対象は「乗車中 → 降車トグル」だけ。目的地クリア（Step 9）とは別。
- 降車と同時に目的地を消すこと。

### 完了条件

- A に乗って A 長押しで降りる → 現在地が更新され、表が新しい経路で埋まる（通信・キーがある前提）。
- 目的地は残る。続けて B を長押しすると B で乗車できる。

### やること

### やってはいけないこと

### 現状
