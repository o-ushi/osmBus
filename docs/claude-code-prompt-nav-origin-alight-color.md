## ステップ 1. ナビ中は、出発地を勝手に更新しない

症状: 目的地を決めてナビしているあいだに、別の画面へ行って地図に戻ると、戻った瞬間の GPS が出発地に差し替わる。経路、乗車停留所、出発地から乗車停留所への徒歩線が、そこを起点に引き直される。

原因は、GPS が届くたびに `_updateOrigin` が `_gps` を書き換え、`origin`（手動の出発地が無ければ `_gps`）で `_replan()` していることです。地図を開き直すと、その最新の `origin` が徒歩線と `initialFit` に使われます。

直したあとのルール:

- ナビ中とは、目的地が設定されているあいだ。ナビを始める瞬間の出発地（手動の出発地があればそれ、無ければそのときの GPS）を経路用の出発地として固定する。
- 固定したあとの GPS 更新では、青い現在地の丸と、乗車中の降車停までの距離、到着アラートだけを動かす。経路用の出発地は変えない。`_replan()` も呼ばない。
- 目的地を決めた時点で GPS がまだ無いときだけ、そのあと最初に届いた 1 点を経路用の出発地にしてよい。2 点目以降は固定する。
- ユーザーが現在地の ↻ を押したときだけ、その時点の GPS を新しい経路用の出発地にして、経路を引き直す。↻ は「次の 1 点を採用する」であり、押したあとも毎回来る GPS で更新し続けない。
- 地図から選んだ手動の出発地は、今まで通り経路用の出発地になる。× で手動を消したときは、ライブの GPS に飛ばさず、固定してある経路用の出発地に戻す。
- ナビ中止（目的地を消す）で固定を解く。目的地が無いあいだは、今まで通り GPS に合わせてよい。
- 画面遷移、地図の作り直し、アプリが前面に戻ったこと、では固定を解かない。プロセスが殺されても、目的地が残っているあいだは同じ出発地に戻す（目的地と同じように保存する）。
- 地図の徒歩線の起点と、出発地のピンは、この固定した点を使う。青い丸は `gps` のまま。

テスト:

- 目的地がある状態で `debugSetOrigin` を 2 回呼んでも、経路用の出発地と旅程は 1 回目のまま。
- 明示的な現在地更新のあとは、2 回目の位置で引き直される。
- 目的地が無いときは、今まで通り後の位置が出発地になる。

ヘルプの「現在地と出発地」（`helpLocationBody`）に、ナビ中は ↻ を押すまで出発地が動かないことを 1 文足す。日・英・越。

## ステップ 2. 降車するバス停を、＋と − でずらす

乗車中に、降車停留所を経路に沿って 1 つずつ変えられるようにする。＋は進行方向の先の停留所、−は 1 つ手前の停留所。変えた停留所を、以降のナビの目標にする。

出し場所は、乗車中の経路地図（`route_map_screen.dart` の降車の行）と、路線図（`bus_route_browser_screen.dart` の下のカード）。どちらも同じ操作で、同じ `TripController` のメソッドを呼ぶ。画面ごとに別の停留所列を持たない。

ルール:

- 停留所の列は、今乗っている路線のカタログ上の停留所。番号表から乗ったときは、そのレグの乗車停留所から終点まで。路線図から乗ったとき（降車の初期値は終点）も、同じ路線の停留所列。
- 初期値は、今の `RidingSession.alightStop`。
- ＋は列の次、−は列の 1 つ前。乗車停留所より手前には行かない。終点より先にも行かない。端ではそのボタンを押せなくする。
- 変えたら `RidingSession.alightStop` をその停留所にする。距離バッジ、到着アラート、地図の降車ピン、乗車中の線の終わりを、その停留所に合わせる。アラートの「もう鳴った」は、目標が変わったのでリセットする。
- 画面を離れても、降車するかナビを中止するまで維持する。乗車の保存（`toJson`）に含め、復元したあとにも効く。
- 乗換の先のレグは変えない。変えるのは今乗っているレグの降車停だけ。

停留所名はボタンのあいだに出す。読み上げは「1つ手前の停留所で降りる」「1つ先の停留所で降りる」。

テスト: 停留所が 4 つの路線で、初期の降車が 3 番目なら、＋で 4 番目、−で 2 番目、もう一度 − しても乗車停留所より前にはならない。変えたあとの残り距離の目標が、その停留所である。

## ステップ 3. 残り距離の背景色を、距離アラートの段に合わせる

対象は距離バッジの背景色（`DistanceColorBand`）。ホームと地図の両方。方眼の地色は変えない。

今は 3km 以上が青、1km 以上が緑、500m 以上が黄、200m 以上が橙、それ未満が赤、で固定です。これを次に置き換える。境目は設定の 3 段のメートルで、アラームがその段で有効かどうかは見ない。

判定はこの順（先に当てはまった色）:

1. 距離アラート 3 のメートル未満 → 赤
2. 距離アラート 2 のメートル未満 → 黄
3. 距離アラート 1 のメートル未満 → 橙
4. 3km 未満 → 緑
5. 3km 以上 → 青

初期値（1000 / 400 / 100）なら、3km 以上が青、1km 以上 3km 未満が緑、400m 以上 1km 未満が橙、100m 以上 400m 未満が黄、100m 未満が赤。ユーザーが段のメートルを変えたら、色の境目もその値に従う。段の大小が入れ替わっていても、上の 1→2→3 の順で判定する。

文字色は色に付ける。青・緑・赤は白、黄・橙は黒。今の対応のまま。

`helpDistanceBody` の色の説明を、この定義に更新する。日・英・越。1km / 500m / 200m の古い説明は残さない。

テスト: 初期値で 3000m は青、2999m は緑、1000m は緑、999m は橙、400m は橙、399m は黄、100m は黄、99m は赤。距離アラート 1 を 2000m にしたときは、1999m が橙、2000m が緑。

## ステップ 4. 停留所の並びが路線の線と明らかに逆行しているときだけ、端末内で直す

原因はアプリの半径ではない。OpenStreetMap の E05（relation `13534191`、Long Biên → Khu đô thị Smart City）で、停留所メンバーの並びが走行順になっていない。道路の way は 251 本のうち隣同士が端点で繋がるものが 247 本で、線自体はほぼ進行方向のまま。アプリは `OverpassApi._detail` のメンバー順を停留所順として保存し、プランナーは乗車停留所より後ろの停留所でしか降りられない。

E05 では「Nhà CT5 KĐT Sông Đà Mỹ Đình」が 34 件中 18 番目なのに、本当はそれより手前の停留所がリストの後ろに入っている。

- 256 Thụy Khuê（CT5 の約 4.7km 手前）
- Chợ Xanh（Xuân Thủy。約 2.1km 手前）
- Long Biên、Quán Thánh、Nguyễn Tri Phương（路線の出発側。約 7km 手前）

出発地に一番近い E05 の停留所がこのどれかだと、CT5 は通過済みになる。その先に目的地（The Garden）から 550m 以内の停留所は無いので、E05 は番号表から消える。同じ方向の 39 と 71 は並びが正しく、CT5 で降りる案内が出た。ユーザーは番号表に E05 が無いので路線図から乗り、降車は終点になっていた。

直すもの:

- OSM には書き戻さない。端末内で、プランナーと路線図が見る停留所順だけを直す。
- 保存済みのカタログにも効かせる。再ダウンロードを必須にしない。読み込んだ `RouteRecord` の停留所とポリラインから、使う直前に一度だけ直す。
- 明らかなときだけ並べ替える。各停留所を、その路線の線に沿った距離（way をメンバー順に繋いだ位置）に落とす。メンバー順のまま測って、後ろに並んでいる停留所が、前の停留所より線上で 1km 以上戻っているものが 1 つでもあれば、並びは誤りとみなす。その路線の、線から 120m 以内に落ちた停留所だけを、線に沿った順に並べ替える。120m より離れた停留所は動かさない。
- どの停留所も 1km 以上戻っていない路線は、そのまま。数十メートルの前後は直さない。
- 線がループしていて、同じ停留所の投影が 2 箇所とも 120m 以内なら、その路線は並べ替えない。
- 線が途中で切れていても、切れたセグメントをメンバー順に繋いで測る。線そのものは作り直さない。
- 並べ替えた順を、番号表、路線図の停留所、乗車中の＋と − が同じものとして使う。

テスト:

- 線が A→B→C→D の順なのに、停留所が A、D、B の順で、B が D より線上で 1km 以上手前。直したあとは A、B、D。B の近くを出発地、D の近くを目的地にすると、その路線が直通で出て、降車は D になる。
- 最初から線の順になっている路線は、停留所の順も中身も変えない。
- 戻りが 1km 未満の路線は、並べ替えない。
- 目的地が線から 550m より遠いケースまで、半径を広げて通さない。
