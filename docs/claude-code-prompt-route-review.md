## ステップ 1. 読み込み時の並べ替えと同梱ファイルをやめる

カタログを読んだあとの停留所順は、OSM のメンバー順のままにする。`StopOrderRepair.snapshot` を読み込み経路から外す。線と逆行していても、ユーザーが直すまで並べ替えない。

同梱の `stop_order.json`、公式順の照合、設定の点検と更新、公式順のヒントを消す。設定の「データ」に停留所順の行は残さない。

端末に残っている `stopOrder.applied` は、次のどちらでも読めるようにする。

- これまでの形: 停留所 ID の配列。その路線の停留所 ID の並べ替えになっているときだけ使う。名前と座標は OSM のものを使う。並べ替えになっていなければ、その路線の記憶は捨てる。
- 新しい形: 停留所の配列。各要素は `id`, `name`, `latitude`, `longitude`。

新しい保存は、新しい形だけを書く。

表示に使う停留所は、記憶が無い路線では OSM の `stops`。記憶がある路線では、覚えた配列を、次の規則で整えてから使う。

- `id` が正で、今の OSM のその路線にまだある: 名前は OSM の名前。座標は覚えた座標（ユーザーが動かした位置を残す）。
- `id` が正で、今の OSM のその路線から消えている: その要素は落とす。
- `id` が負: ユーザーが足した停留所。名前も座標も覚えたものを使う。
- 整えた結果が 2 件未満なら、その路線の記憶は捨てて OSM の並びに戻す。

番号表、プランナー、経路地図、路線図、降車停の − ＋ は、この表示用の停留所を見る。到着距離は、この座標で測る。

テスト:

- 線の上で 1km 以上戻っている路線を読み込んでも、`stops` の順は OSM のまま。
- 古い ID 配列が、その路線の停留所の並べ替えなら、表示順はその順。一つでも知らない ID なら、その路線は OSM の順。
- 覚えた正の ID が路線から消えたら、その要素だけ落ちる。残ったユーザー追加（負の ID）は残る。残数が 2 未満なら記憶ごと捨てる。

## ステップ 2. ユーザーが確認を求めた路線だけ、所見を作る

所見を作るのは、ステップ 3 の「この路線を確認」を押したときだけ。画面を開いたときには走らせない。

入力は、今の表示用の停留所と、その路線のポリライン、カタログ内の他路線。閾値は次で固定する。

- 線の上: 停留所から線まで 120m 以内（`StopOrderRepair.onLineMeters`）。
- 順序の戻り: 線上で 1km 以上（`StopOrderRepair.backtrackMeters`）。
- 場所の差し替え候補: 同じ名前で、この路線の線から 120m 以内、かつ今の停留所から 150m より遠い。
- 過不足の候補: この路線の線から 50m 以内にあり、この路線のどの停留所からも 80m より遠い。
- 名前は、前後の空白、連続する空白、大文字小文字、ベトナム語のダイアクリティカルを無視して一致したものだけ。短い方が長い方に含まれる、では一致にしない。

同じ `ref`（前後の空白と大文字小文字だけ無視）で別の `relationId` を、比較用の相手にする。`from` と `to` が入れ替わっている路線を優先する。それが無ければ、停留所 ID を一番多く共有する 1 本。共有数が同点なら、相手は無しとする。

所見は 3 種類。各種類が空なら、その種類は「気になる点はありません」。

### 順番

線から 120m 以内の停留所を表示順に見て、前の停留所より線上で 1km 以上戻っているものがあるときだけ、順序の所見を 1 件出す。同じ停留所 ID が 2 回出る路線は、この所見を出さない。

文は、戻っている停留所について「線に沿うと、どの停留所とどの停留所のあいだか」を書く。提案は `StopOrderRepair.repair` と同じ並べ替え（線から 120m 以内だけを線の順にし、離れた停留所は元の位置に残す）。この提案は、ユーザーが「これを使う」を押すまで保存しない。

相手の路線があるときは、共有している停留所 ID の前後を、相手側の順を逆にして比べる。逆にしても前後が違うときは、順序の所見に「復路と、線の向きを考慮しても前後が違います」と 1 行足す。この 1 行だけでは提案にしない。戻りが無い路線に、この 1 行だけ出さない。

### 場所

線から 120m より遠い停留所ごとに 1 件。文に、線からのおおよその距離（メートルの整数）を入れる。

差し替え候補は、カタログの他路線にある停留所で、名前が一致し、この路線の線から 120m 以内、今の停留所から 150m より遠く、この路線の表示にまだ入っていないもの。複数あれば線に一番近い 1 件。候補があるときだけ「この停留所に差し替える」を出せる。候補が無ければ距離だけ書き、差し替えボタンは出さない。座標を新しく作らない。

### 停留所の過不足

次の 3 つの一覧だけ。それぞれ 8 件まで、線に近い順。0 件の一覧は出さない。3 つとも 0 件なら、この種類は「気になる点はありません」。

- 相手の路線にあって、この路線の線から 50m 以内、この路線のどの停留所からも 80m より遠い停留所。見出しは「復路にあって、この路線の線の近くにあるが、この路線に入っていない停留所」。
- それ以外の路線の停留所で、同じ条件のもの。見出しは「他の路線の停留所で、この線の近くにあるが、この路線に入っていないもの」。
- この路線にあって、相手の路線に同じ ID も、80m 以内の停留所も無いもの。見出しは「この方向にだけある停留所」。相手の路線が無いときは、この一覧は出さない。

この種類に「これを使う」は付けない。足すのも消すのもユーザーが行う。シートには「自動では足しません」と書く。

テストはウィジェットでなくてよい。線と停留所を縮めたフィクスチャで、次を確認する。

- 1km 以上戻っている路線では順序の所見が 1 件あり、提案を適用した順では `StopOrderRepair` と同じ順になる。戻っていない路線では順序の所見が無い。
- 線から 400m 離れ、他路線に同名で線の近くにある停留所があるときは、場所の所見がその 1 件を差し替え候補にする。同名が無ければ候補は無く、距離だけがある。
- 相手の路線の停留所がこの線から 50m 以内にあり、この路線に入っていなければ、過不足の一覧に出る。適用用の提案には入らない。
- 短い名前が長い名前に含まれるだけでは、場所の候補にも過不足の同名扱いにもしない。

## ステップ 3. 入口を一つにして、所見ごとに採用できるようにする

`StopOrderEditRow` を、次の 1 行に変える。オレンジの警告にはしない。

- 記憶が無い: 「この路線を確認」。
- 記憶がある: 「直した順を使っています」。

タップでレビューのシートを開く。シートは押したときにステップ 2 を計算する。

シート:

- 題は「この路線の確認」。副文に `ref` と方面。
- 順番、場所、停留所の過不足、の順。
- 順序の所見には「これを使う」。押すと、その提案の停留所配列をステップ 1 の新しい形で保存し、シートは開いたまま所見を計算し直す。他の所見は保存しない。
- 場所の所見で候補があるものには「この停留所に差し替える」。押すと、その 1 件だけを候補の `id`、名前、座標に置き換えて保存し、シートは開いたまま計算し直す。候補が無い所見にボタンは付けない。
- 過不足に適用ボタンは付けない。「自動では足しません」を出す。
- 下に「自分で直す」。記憶があるときは「OSM の並びに戻す」も出す。戻すはその路線の記憶を消し、シートを閉じる。表示は OSM のメンバー順に戻る。

「これを使う」も「この停留所に差し替える」も、カタログのファイルは書き換えない。

テスト:

- 順序の所見だけ採用すると、その路線の表示順は提案の順になる。別の路線は変わらない。場所の差し替えは、その 1 件の ID と座標だけが変わる。
- 「OSM の並びに戻す」で記憶が消え、表示は OSM のメンバー順に戻る。読み込み時の並べ替え後ではない。

## ステップ 4. 自分で直す

「自分で直す」で、今の表示順の停留所を全部出すシートを開く。記憶がある路線でも、並べ替え・追加・削除・位置の変更を続けられる。一度保存したあとにドラッグを禁止しない。

- ドラッグで順番を入れ替える。
- 各行を削除できる。表示が 2 件のときは削除できない。
- 「停留所を足す」で、まずステップ 2 の過不足のうち、復路と他路線の候補を一覧する。選ぶと、その停留所の `id`、名前、座標を末尾に足す。すでに表示にある ID は一覧に出さない。
- 同じシートに「地図で場所を指定」。`BusMap` にその路線の線を出し、長押しでピンを置く。`allowGoogle: false`。名前の入力が空でなく、ピンがあるときだけ足せる。足した停留所の `id` は負の整数で、この端末で重ならない。末尾に足す。この停留所は他の路線のメンバーにはしない。
- 緯度と経度の数値入力は、地図の下に畳んで置く。両方とも数値として読めたときだけピンを動かす。長押しでも、その欄の数値はピンの位置に合う。
- 既存の行の「場所」でも、同じ地図と数値入力で、その行の座標だけを変える。正の ID の名前は変えない。負の ID は名前も変えてよい。
- ボタンは「この順で使う」。開いたときから 1 件も違わなければ押せない。押すと新しい形で保存してシートを閉じ、番号表、経路地図、路線図、− ＋ がその停留所を見る。
- 記憶があるときは「OSM の並びに戻す」も出す。

テスト:

- ドラッグした順を保存すると、その路線の表示順がその順になる。別の路線は変わらない。
- 負の ID の停留所を足して保存すると、その名前と座標が表示に残る。他の路線の `stops` には入らない。
- 1 件削除して保存すると、その停留所は表示から消える。2 件のときは削除できない。
- 正の ID の座標を変えて保存すると、表示の座標は変えた値で、名前は OSM の名前のまま。
- 保存したあとに、もう一度開いて順番を変えて保存できる。
- 「OSM の並びに戻す」で、足した停留所も座標の変更も消え、OSM のメンバー順に戻る。
