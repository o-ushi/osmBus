## Step 1 — 地図上の自分アイコン：乗車中／降車中で色分け＋枠を太く

### やってよい範囲

- `TransitMapMarkerIcons.myLocationDot` とその呼び出し側
- `_GoogleMSMapWrapper` / `Coordinator.myLocationMarker` のアイコン更新
- 乗車状態を地図に渡すための最小限の引数追加（`GoogleMapView` / `syncMapLiveLocation` 周辺）

### 現状

- `osmBus/Views/TransitRouteMapView.swift` の `TransitMapMarkerIcons.myLocationDot()` は常に `UIColor.systemBlue`。
- マーカー作成時だけ `marker.icon` をセットし、その後は座標移動のみ。乗車状態でアイコンを差し替えていない。
- Google SDK の `isMyLocationEnabled` はオフ。自前 `GMSMarker` が「自分」。

### やること

1. `myLocationDot` を **塗り色を引数で受け取れる**形にする（例: `fill: UIColor`）。デフォルトは降車中色（`AppTheme.brandBlue` 相当）。
2. **枠線を現行より太く**する（白リングを広げる／内側ドットを少し小さくする等）。地図のポリラインやピンに埋もれないこと。直径は大きくしすぎない（だいたい 22→26〜28pt 程度を上限の目安）。
3. 乗車中は橙色、降車中は青でアイコンを描画する。
4. `ridingState` の変化でアイコンを **再描画・差し替え**する。位置更新だけだと色が変わらない現状を直す。
5. `TransitRouteMapView` と `BusRouteMapView` の両方で同じ見た目になること（共通の `GoogleMapView` / wrapper 経由なら一箇所で足りる）。

### やってはいけないこと

- バス停ピン（boarding / alight）の色仕様をこのステップで変えること。
- `TransitBusLineBadgeLabel` の色ロジックを別仕様にすること（揃えるのは「自分アイコン」側）。
- 新しい画像アセットの追加。SF Symbol / Core Graphics で完結させる。
- 乗車状態モデル（`RidingState`）の意味を変えること。

### 完了条件

- 未乗車・降車後: 自分アイコンがブランド青＋太い白枠。
- 乗車開始後: 橙色＋太い白枠に切り替わる（地図を開き直さなくても反映）。
- `TransitRouteMapView` と `BusRouteMapView` の両方で確認できる実装になっている。
- ビルドが通る。

## Step 2 — 路線図の過去検索結果を一覧で見られるようにする（データ＋リストUI）

### やってよい範囲

- `BusLineMapStore`（既存の端末キャッシュ）の読み出し API 拡張（必要なら）
- 新規の一覧 View（例: `BusRouteMapHistoryView`）
- 一覧から路線を選んだときの `BusRouteDetail` 復元・表示接続
- `ja` / `en` / `vi` の一覧用文字列

### 現状（重要）

- **検索クエリ履歴専用の UI はない**。
- ただし `BusLineMapStore` が、一度取得した OSM 全線（`relationId` / `ref` / `name` / stops / polyline / `lastUsedAt`）を `Application Support/osmBus/bus-line-maps.json` に最大 40 件溜めている。
- `remember(_:)` は `BusRouteMapView.loadRoute` などから呼ばれている。
- 代替乗車判定用の内部キャッシュであり、ユーザー向け一覧にはまだ出ていない。

### やること

1. **新しいストアを作らず**、`BusLineMapStore` を一覧の正本にする。必要なら `allRecords()` / `recentDetails()` のような読み出しを追加する（`lastUsedAt` 降順）。
2. 一覧 UI を作る。各行に少なくとも次を出す:
   - バス番号（`ref`）
   - 路線名・from/to があれば補助表示
   - 最終利用が分かるなら相対日時でも可（無くてもよい）
3. 行タップでその路線を地図に載せる（既存の `BusRouteDetail` 復元 → `searchState = .loaded(...)` 相当。ネット再取得は必須にしない。キャッシュから即表示）。
4. 空のときは短い空状態メッセージを出す。
5. 削除（1件 or 全クリア）が既存 `clear` / レコード単位削除で自然に足せるなら付ける。無理ならこのステップでは「見る＋開く」だけでよい（削除は Step 3 でも可）。
6. 同意撤回で既存どおり `BusLineMapStore` が消える前提を崩さない（`ThirdPartyDataConsent`）。

### やってはいけないこと

- `DestinationHistoryStore` や Keychain に路線図履歴を二重保存すること。
- Overpass を一覧表示のたびに全件叩き直すこと。
- メイン画面の行き先履歴 UI を路線図用に流用して意味を混ぜること（見た目の参考は可）。

### 完了条件

- 過去に路線図で読んだ路線が、オフラインでも一覧から開ける。
- 同じ `relationId` は重複せず、最新利用が上（または同等の分かりやすい順）。
- 3言語の空状態・タイトル等がある。
- ビルドが通る。**このステップではツールバーボタンはまだ必須ではない**（Step 3 で繋ぐ）。プレビューや一時的な入口があってもよいが、本番入口は Step 3。

## Step 3 — 路線図ツールバーに履歴ボタンを置く（キーボードの横）

### やってよい範囲

- `BusRouteMapView.toolbarContent`（`.navigationBarTrailing` の `HStack`）
- Step 2 の一覧を sheet / navigation destination で出す接続
- 必要な accessibility / ローカライズキー

### 現状

`BusRouteMapView` の trailing はおおよそ次の順（未乗車時）:

1. 緑の `bus.fill`（乗車開始）※路線ロード時
2. `trash`（クリア）※路線ロード時
3. `keyboard` / `keyboard.chevron.compact.down`（テンキー表示切替）

### やること

1. **キーボードボタンのすぐ横**（同じ `HStack` 内）に、一覧へ行くボタンを追加する。
   - 推奨 SF Symbol: `list.bullet` または `clock.arrow.circlepath`（履歴だと分かるもの。新規アセット禁止）
   - 配置: キーボードの **左隣**（キーボードが右端のまま残る）を推奨。既存の乗車開始・クリアより履歴の方がキーボードに近いこと。
2. タップで Step 2 の一覧を表示（`.sheet` 推奨。既存の `candidateSheet` と衝突しないこと）。
3. 一覧で路線を選んだら sheet を閉じ、地図にその路線を表示し、テンキーは閉じてもよい。
4. 乗車中モード（`ridingActive` / `isRidingMode`）では、既存どおり trailing がバッジ中心なら、履歴ボタンは出さなくてよい（browse モードが主対象）。
5. VoiceOver ラベルを 3 言語で追加（例キー: `路線図_履歴`）。

### やってはいけないこと

- キーボードボタンを別の場所に移すこと。
- メインの More メニューだけに履歴を逃がして、路線図画面から辿れなくすること。
- Step 1 のアイコン色や Step 2 以外の大きなリファクタ。

### 完了条件

- browse の路線図を開く → 右上でキーボードの横に履歴ボタンがある。
- 履歴 → 行タップ → 地図に路線が載る、が一連で使える。
- テンキーの開閉は従来どおり動く。
- ビルドが通る。
